# XH-202625 正式 25 类数据集对接设计

日期：2026-06-21

## 1. 目标

将比赛正式训练数据接入现有遥感检测工程，形成可复现的 25 类水平框训练、
滑窗推理、COCO JSON 导出、比赛规则评估和 Gradio 演示闭环。

模型训练和结果文件保留官方 25 个细分类 ID；比赛指标同时按舰船、飞机、车辆
三个大类聚合，以满足评分方案对总体刚性指标和三大类排名的要求。

第一阶段不以最终精度为验收条件，而是要求：

1. 数据划分无同源裁剪泄漏；
2. 25 类 HBB 模型完成一轮 GPU 冒烟训练；
3. 正式图片可以完成推理、可视化和 JSON 导出；
4. 验证集可以输出总体及三大类 Recall、FDR；
5. 训练、推理和 Demo 使用同一类别定义和模型权重。

## 3. 关键设计决策

### 3.1 使用 25 类 HBB 模型

正式模型采用 Ultralytics 水平框检测模型，首个基线使用 `yolo26s.pt`，不再使用
此前公开数据阶段的 `yolo26s-obb.pt`。

原因：

- 官方标签已经是水平框，直接训练 HBB 不需要伪造目标方向；
- 官方结果需要保留 0-24 类 ID；
- HBB 推理和后处理速度更适合 10,000×10,000 大图的 20 秒限制；
- 25 类输出保留飞机型号信息，后续可以进行细分类长尾优化；
- 比赛评估时仍可稳定聚合为舰船、飞机和车辆三大类。

公开数据 OBB 路线保留为历史基线，不删除，但正式比赛配置默认使用 HBB。

### 3.2 细分类与大类映射

建立唯一的类别目录模块，作为训练配置、推理、评估、导出和前端的共同依赖：

```text
0-3   -> ship
4-23  -> aircraft
24    -> vehicle
```

25 个官方名称严格使用 `data/dataset.yaml` 中的名称。任何模块不得自行复制另一份
类别表，避免训练 ID、可视化名称和提交 JSON 不一致。

### 3.3 保留 25 类提交结果

COCO Detection JSON 中的 `category_id` 保留官方 0-24 ID：

```json
{
  "image_id": 1,
  "category_id": 8,
  "bbox": [100.0, 200.0, 40.0, 25.0],
  "score": 0.92
}
```

导出器接受配置声明的合法类别集合，不再硬编码 `{0, 1, 2}`。在最终提交规范发布
前，`image_id` 使用显式映射文件生成，禁止依赖文件遍历顺序。

## 4. 数据划分与产物

### 4.1 输出目录

数据准备命令生成独立目录，不复制 1.2 GB 原图，优先使用硬链接，失败后使用符号
链接，再失败才复制：

```text
datasets/xh25/
├── dataset.yaml
├── images/
│   ├── train/
│   └── val/
├── labels/
│   ├── train/
│   └── val/
├── manifests/
│   ├── train.txt
│   ├── val.txt
│   └── source-groups.json
└── reports/
    ├── dataset-analysis.json
    └── dataset-analysis.md
```

### 4.2 同源分组

验证集不得与训练集包含同一原始场景的不同裁剪。分组规则按以下顺序执行：

1. 对文件名移除 `_cropN`、`_cropNNNN` 等裁剪后缀；
2. 同一基础名称的图像归入同一组；
3. 对没有裁剪后缀的图像按单图分组；
4. 额外输出图像尺寸和感知哈希审计报告，标记跨组近重复候选；
5. 不把所有 `MAR20_*` 图像错误合并为单个组。

感知哈希在第一阶段只用于审计和报告，不自动合并不确定的图像，避免将大量飞机
样本强制放入同一集合。确认的近重复图可在后续配置中增加显式分组覆盖。

### 4.3 分层划分

默认验证集比例为 15%，随机种子固定为 42。以同源组为最小单位执行多标签分层
划分，目标是同时接近：

- 总图像数量 85%/15%；
- 25 类目标框分布 85%/15%；
- 25 类含目标图像数量 85%/15%；
- 舰船、飞机、车辆三个大类分布 85%/15%。

约束：

- 同一同源组不能跨集合；
- 每个官方类别必须在 train 和 val 中都出现；
- HM、LQS、FSC 等稀有类优先保证验证集中至少有两个同源组；
- 若约束无法同时满足，命令失败并输出冲突原因，不静默生成有缺类的验证集；
- 重复运行必须生成相同清单。

### 4.4 数据校验

准备命令在创建链接前检查：

- 图像和标签一一对应；
- 图像可读取、宽高为正；
- 标签每行恰好包含 5 个字段；
- 类别 ID 位于 0-24；
- 坐标有限且归一化范围合法；
- 宽高大于零；
- 反归一化后的框不越出图像；
- 划分后 train、val 无文件名和同源组交集。

## 5. 模型训练设计

训练入口继续使用 `xh-detect train`，但正式配置扩展为可显式设置：

- HBB 模型权重；
- epochs；
- image size；
- batch；
- workers；
- AMP；
- patience；
- project/name；
- seed；
- resume。

第一阶段命令目标：

```bash
xh-detect train \
  --dataset-yaml datasets/xh25/dataset.yaml \
  --model yolo26s.pt \
  --epochs 1 \
  --image-size 1024 \
  --device 0
```

冒烟训练确认数据加载、前向、反向、验证和权重保存。正式基线再运行 30-50 epoch。
第一版不修改网络结构，不同时引入重采样、Copy-Paste 和损失重加权，保证基线可解释。

正式优化按以下顺序进行：

1. 建立原始 25 类基线；
2. 调整全局及分类别置信度阈值；
3. 对稀有类使用类别均衡采样；
4. 对 HM、LQS、FSC 使用受控 Copy-Paste；
5. 加入 hard-negative mining；
6. 比较模型规模和输入尺寸；
7. 每项改动独立消融。

## 6. 推理架构

### 6.1 通用检测器接口

现有内部 `BoxPrediction` 四点多边形表示继续保留。HBB 检测器将 Ultralytics
`boxes.xyxy` 转换为：

```text
(xmin, ymin), (xmax, ymin), (xmax, ymax), (xmin, ymax)
```

这样滑窗坐标回映、缓存和导出可以复用，无需重写完整流水线。

检测器按模型任务读取 HBB `boxes` 或 OBB `obb`，正式配置明确指定 `task: detect`，
不进行不透明的自动降级。

### 6.2 滑窗与合并

正式数据裁剪图可直接缩放推理；10,000×10,000 测试图继续使用现有滑窗流水线：

1. 以 1024×1024、20% 重叠切片；
2. GPU 批量 FP16 HBB 推理；
3. 恢复全图坐标；
4. 删除明显的切片边缘残框；
5. 按 25 个细分类执行 class-wise HBB NMS；
6. 输出 25 类结果和三大类汇总。

细分类 NMS 可避免不同飞机型号互相抑制。比赛总体评估另行聚合，不在后处理阶段
丢失细分类。

### 6.3 配置

新增正式配置 `configs/xh25-hbb.yaml`，至少包含：

- `task: detect`；
- `model_path`；
- 25 类名称和阈值；
- 大类映射；
- image/tile size；
- overlap、batch size、merge IoU、edge margin；
- device、half。

配置加载器校验类别 ID 必须连续覆盖 0-24，类别阈值允许逐类覆盖。

## 7. 比赛规则评估

评估器提供两个互补视图。

### 7.1 官方总体指标

评分文档要求三类目标合并计算刚性指标，因此总体匹配不以 25 个细分类是否相同为
前提。预测按置信度降序贪心匹配尚未匹配的真值：

- 真值为车辆（官方 ID 24）时 IoU 阈值为 0.35；
- 其他真值（舰船或飞机）时 IoU 阈值为 0.50；
- 每个预测和真值最多匹配一次；
- 重复预测计入 FP。

总体输出 TP、FP、FN、Recall 和 FDR。

### 7.2 三大类指标

舰船、飞机、车辆分别进行大类一致的匹配，用于评分方案中的三类独立排名和误差
分析。细分类预测错误但大类正确时，可计入该大类检测 TP；跨大类预测不能匹配。

### 7.3 25 类诊断指标

额外输出 25 类 class-aware 指标，仅用于长尾分析，不冒充官方刚性指标。报告必须
明确区分：

- `overall_class_agnostic`；
- `by_coarse_class`；
- `by_fine_class`。

阈值扫描同时支持全局阈值和 25 类阈值配置，并优先搜索满足：

```text
Recall >= 0.85
FDR <= 0.20
```

的可行区间。

## 8. 前端 Demo

正式 Demo 默认加载 HBB 模型，页面包含：

- 上传正式遥感图像；
- HBB 检测结果；
- 每个框显示官方细分类名称和置信度；
- 舰船、飞机、车辆数量汇总；
- 可折叠的 25 类明细；
- 预处理、推理、后处理和总耗时；
- 下载保留 25 类 ID 的 COCO JSON；
- 上传真值时显示总体、三大类和 25 类诊断指标；
- 内置三张不含敏感路径信息的正式数据演示样例。

正式 HBB 配置不再把 OBB/HBB 切换作为主要控件。历史 OBB 配置仍可通过命令行和
旧配置运行。

## 9. 失败处理

- 原始数据缺失或布局错误：准备命令立即失败并列出路径；
- 标签非法：不静默修复，报告文件名、行号和原因；
- 稀有类无法满足划分约束：停止并要求调整比例或显式分组；
- 链接创建失败：依次回退到符号链接和复制，并记录实际方式；
- 模型类别数量不是 25：启动推理时失败；
- 模型任务不是 HBB detect：正式配置启动时失败；
- JSON 中存在未知类别、非法坐标、NaN 或重复记录：阻止导出；
- 无预测：输出合法空 JSON 和零目标统计；
- CUDA OOM：降低 batch 重试，但不静默降低 image size；
- 训练中断：保留 `last.pt`，支持显式 `--resume`。

## 10. 测试策略

### 10.1 数据测试

- 解析合法和非法 YOLO HBB 标签；
- 25 类 ID 边界；
- `_cropN` 同源分组；
- 同源组不跨 train/val；
- 固定种子结果可复现；
- 每个类别在两边均存在；
- 稀有类约束无法满足时明确失败；
- 硬链接、符号链接、复制回退；
- 数据报告统计与清单一致。

测试使用临时小数据，不把完整正式数据加入单元测试。

### 10.2 推理与导出测试

- Ultralytics HBB `xyxy` 转四点多边形；
- 0 和 24 类边界合法；
- 25 类阈值过滤；
- HBB 滑窗坐标回映；
- 同细分类重复框合并；
- 不同细分类框不互相抑制；
- COCO JSON 接受 0-24，拒绝其他 ID；
- Demo 汇总同时包含三大类和细分类。

### 10.3 评估测试

- 总体 class-agnostic 匹配；
- 跨细分类、同大类匹配；
- 跨大类不匹配；
- 车辆 IoU=0.35 边界；
- 舰船和飞机 IoU=0.50 边界；
- 一个真值只能产生一个 TP；
- 空预测、空真值；
- 总体、三大类和 25 类报告彼此独立。

### 10.4 GPU 集成测试

- 正式数据 1 epoch HBB 训练；
- 至少三类各选一张图片推理；
- CLI 和 Gradio 对同一图输出一致；
- 生成并严格校验 COCO JSON；
- 10,000×10,000 合成图在 4090 上重新基准；
- 最终提交前在 3090 或同等算力环境复测 20 秒限制。

## 12. 验收标准

满足以下条件即完成“正式数据对接”：

1. 一条命令从 `data/` 生成可复现的 `datasets/xh25/`；
2. train/val 无同源组交集，且 25 类在两边均有样本；
3. 数据报告与实际标签统计一致；
4. `yolo26s.pt` 在 4090 上完成 1 epoch；
5. 正式数据图片通过 CLI 和 Demo 生成 HBB 可视化；
6. JSON 保留 0-24 类 ID 并通过严格校验；
7. 评估报告区分总体、三大类和 25 类诊断指标；
8. 全量单元测试、格式检查和静态检查通过；
9. 10,000×10,000 基准仍满足当前 4090 演示目标；
10. 原始 `data/` 未被修改。

## 13. 后续优化边界

本次对接完成后再单独设计长尾优化，不在基线接入中同时引入。候选方向包括：

- 类别均衡采样；
- 稀有类 Copy-Paste；
- focal/varifocal 类损失对比；
- hard-negative mining；
- 粗细粒度多任务学习；
- 伪标签和教师学生蒸馏；
- 针对 HM、LQS、FSC 的专用模型或二阶段复核；
- TensorRT FP16。

每项优化必须与 25 类原始基线进行独立消融，并报告总体 Recall/FDR、三大类指标、
稀有类指标和速度。
